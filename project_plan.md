PROJECT NAME

RRKM-ME-pipeline (working title)

PROJECT PURPOSE

Build a complete, reproducible, open-source pipeline from ab initio
electronic structure through pressure- and temperature-dependent rate
constants for a gas-phase combustion reaction, and document every
approximation involved clearly enough that a reviewer with no prior context
can follow it end to end.

The goal is not a demonstration that the pipeline "works" on a toy case. The
goal is a genuine, if small, scientific artifact:
1. Characterize the CH3 + O potential energy surface (multiple product
   channels) using open-source electronic structure tools.
2. Extract vibrational frequencies, rotational constants, and relative
   energies needed for RRKM/master-equation theory.
3. Run master-equation kinetics using an open-source, license-free solver
   (MESS) to obtain pressure- and temperature-dependent rate constants and
   branching ratios.
4. Validate against literature/ATcT-referenced values and discuss where the
   approximations used (level of theory, harmonic oscillator/rigid rotor
   assumptions, etc.) are likely to break down.
5. Maintain a GitHub repository documenting the pipeline and its
   limitations: github.com/juanmagnet0n/RRKM-ME-pipeline (exact name TBD)

USER BACKGROUND

PhD in physical chemistry (FIU), dissertation work in combustion kinetics
using DFT, CCSD(T), and RRKM/master-equation theory on resonance-stabilized
free radical systems (propargyl, allyl) with atomic and molecular oxidants,
using Gaussian, MOLPRO, and MultiWell on HPC systems, validated against
experimental kinetics data. This project intentionally uses a different,
fully open-source toolchain (Psi4 instead of Gaussian/MOLPRO, MESS instead
of MultiWell) so the pipeline is runnable by anyone who clones the repo
without a commercial license. This is a deliberate reproducibility choice,
not a claim that these tools were used in the dissertation work itself; that
distinction should be stated explicitly in the README and not blurred.

CORE OBJECTIVE

Take CH3 + O, a benchmark multi-channel combustion reaction with established
literature and ATcT-referenced thermochemistry, and build a fully documented
electronic-structure-to-rate-constant pipeline, reproducing published rate
constants and branching ratios to within a stated, honestly discussed
tolerance.

WHY CH3 + O (not a simpler system)

CH3 + H -> CH4 would be simpler (single well, no branching) but would not
demonstrate the multi-channel character that is the actual scientific
content of combustion kinetics work. CH3 + O has several competing product
channels (CH2O + H, HCO + H2, CO + H2 + H, among others), giving genuine
branching ratio predictions to validate, which is much closer to the kind of
system in the dissertation work (propargyl + O, allyl + O2) than a
single-channel toy case, without requiring multireference treatment the way
propargyl + O's excited-state recombination pathway does. This system is
single-reference-dominated at its stationary points, so CCSD(T) is an
appropriate and defensible level of theory here; that assumption should be
checked with a T1 diagnostic early and stated explicitly rather than
assumed.

TOOLCHAIN (planned, open-source only)

- Electronic structure: Psi4 (DFT for geometry optimization and initial
  frequency screening; CCSD(T) for final single-point energies).
- Thermochemistry: manual or lightly scripted extraction of vibrational
  frequencies, rotational constants, and zero-point energies from Psi4
  output.
- Master-equation kinetics: MESS (Georgievskii/Klippenstein), the standard
  open-source RRKM/master-equation solver in the combustion kinetics
  community. Input files built and version-controlled directly, not
  auto-generated by a black-box wrapper, so the physics is visible and
  auditable in the repo.
- Validation reference: literature rate constants for CH3 + O (to be
  identified and cited explicitly, not assumed from memory) and, where
  available, ATcT-referenced thermochemistry for reactants/products.
- Python for data handling, unit conversion, and plotting (matplotlib or
  OriginPro-style clean figures).

PHASES (planned)

- **Phase 1: Stationary point characterization.** Optimize geometries and
  compute harmonic frequencies for CH3, O, and the relevant product channels
  at a DFT level (functional TBD, likely B3LYP or wB97X-D for consistency
  with dissertation-era choices) using Psi4.
- **Phase 2: Multireference diagnostic check.** Before committing to
  single-reference CCSD(T), run T1 diagnostics (and %TAE[(T)] if feasible)
  on all stationary points to confirm this system is appropriately treated
  single-reference. This is a direct methodological carryover from the
  propargyl + O multireference triage note, applied here as a sanity check
  rather than assumed.
- **Phase 3: CCSD(T) single-point energies.** Refine relative energies at
  the CCSD(T) level for all stationary points identified in Phase 1.
- **Phase 4: MESS input construction and master-equation kinetics.** Build
  MESS input files by hand (not via an opaque generator), documenting every
  physical choice (energy grid, collision model, bath gas) in
  mess_input_walkthrough.md. Run master-equation calculations to get
  pressure- and temperature-dependent rate constants and branching ratios.
- **Phase 5: Validation and honest limitations discussion.** Compare against
  literature/ATcT-referenced values. Discuss explicitly: where the harmonic
  oscillator/rigid rotor approximation is likely weakest, what level-of-
  theory sensitivity looks like, and where this pipeline's results should
  and should not be trusted relative to the original literature.

WHAT THIS PROJECT IS NOT

- Not a claim that this pipeline is more accurate or more rigorous than
  Gaussian/MOLPRO/MultiWell-based dissertation work; it is a deliberately
  open-source-only rebuild for portability and reviewer accessibility.
- Not a novel scientific result. CH3 + O is a benchmark system chosen
  specifically because it is well characterized in the literature; the value
  of this repository is in the pipeline's transparency and reproducibility,
  not in new chemistry.
- Not a substitute for QC2. This is a separate, classical-kinetics-focused
  repository demonstrating the DFT/CCSD(T)/RRKM-ME side of the skill set;
  QC2 demonstrates the quantum computing side. Keep them separate and
  cross-reference rather than merge.

STYLE OF HELP (carried over from QC2 conventions)

- Direct, technical, operational.
- Separate facts from interpretation; state assumptions explicitly.
- Distinguish toy/sanity-check results from scientifically meaningful ones.
- No invented citations, no invented benchmark values -- literature rate
  constants and ATcT values must be looked up and cited properly before
  being used for validation, not assumed from memory.
- Same technical note template as QC2 (Direct answer / Why this matters /
